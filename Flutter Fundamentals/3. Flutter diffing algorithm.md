# 🧠 Flutter's "Diffing Algorithm" (Element Tree Comparison)

When Flutter **rebuilds**, it **does not** rebuild everything blindly.

It uses a **smart diffing algorithm** to **compare the new widget tree** with the **old widget tree**, and decide:

- 🤔 **Reuse** old widget?
- 🔥 **Create** a new widget?
- 🧹 **Delete** old widget?

---

## 🏛️ Flutter Tree Structure (important to know)

Flutter actually manages **3 parallel trees** during runtime:

| Tree | Purpose |
| --- | --- |
| Widget Tree | Blueprint (what you want) |
| Element Tree | Live connection between widget and rendering |
| RenderObject Tree | Actual layout & painting (pixels!) |
- **Widget** = Immutable config
- **Element** = "Instance" living between widget and render
- **RenderObject** = Heavy engine doing layout, paint, hit test

---

# 🎯 How Diffing Works (Step-by-Step)

Let's say you have this `build()` function:

```dart
Widget build(BuildContext context) {
  return Column(
    children: [
      Text('Hello'),
      Text('World'),
    ],
  );
}

```

Then later, you change it to:

```dart
Widget build(BuildContext context) {
  return Column(
    children: [
      Text('Hello!'), // <-- Text changed
      Text('World'),
    ],
  );
}

```

**Flutter will:**

1. See that **Column** is still a Column → ✅ Reuse existing Element
2. Go inside `children`
3. Compare first child:
    - `Text('Hello')` vs `Text('Hello!')`
    - Same **runtimeType** (`Text`) → can reuse Element.
    - But **different text** → rebuild **only** that text widget
4. Compare second child:
    - `Text('World')` vs `Text('World')`
    - Identical → ✅ no change

⚡ **Result**:

Only `Text('Hello')` gets updated!

Everything else stays untouched.

This is **super efficient**.

---

# 🏎️ Key Rules Flutter Uses for Diffing:

| Rule | Meaning |
| --- | --- |
| **Same Type** | If old widget and new widget are same type (e.g., both `Text`), reuse the Element. |
| **Different Type** | If type changes (e.g., `Text → Icon`), destroy old Element and create new one. |
| **Key Changes** | If a `Key` is different, Flutter treats it as a totally new widget. |

---

# 🎯 Why Use Keys in Flutter?

Sometimes **two widgets are the same type**, but **you don't want Flutter to reuse** —

e.g., swapping list items.

Then you use **`Key`** to tell Flutter:

> "Hey, this is a different widget even if it looks similar!"
> 

Example:

```dart
ListView(
  children: [
    Container(key: ValueKey('A'), child: Text('Item A')),
    Container(key: ValueKey('B'), child: Text('Item B')),
  ],
)

```

If you swap them, Flutter sees the `Key` change and knows it must rebuild.

# 🧠 Full Mind Map Diagram

```
User triggers setState()
      ↓
Flutter schedules a build
      ↓
build() returns a new Widget Tree
      ↓
Element Tree compares old and new widgets:
      ↓
- If runtimeType is same → reuse Element
- If different → replace Element
- If Key is different → replace Element
      ↓
Widgets updated efficiently
      ↓
RenderObjects updated if needed
      ↓
Screen updated!
```
