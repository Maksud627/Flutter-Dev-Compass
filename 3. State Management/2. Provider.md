`Provider` is a wrapper around **InheritedWidget** that makes it easier to manage and share **state/data** across your widget tree, without needing to manually pass data down through constructors.

- Helps manage and listen to app-wide state.
- Keeps UI and logic separated (good architecture).
- Automatically rebuilds widgets that depend on changed data.

- ***Basic Provider example***
    
    `ChangeNotifier.dart`
    
    ```dart
    import 'package:flutter/material.dart';
    
    class CounterProvider with ChangeNotifier {
      int _counter = 0;
    
      int get counter => _counter;
    
      void increment() {
        _counter++;
        notifyListeners(); // Tells all listening widgets to rebuild
      }
    }
    ```
    
    `main.dart`  (wrapping CounterProvider with ChangeNotifier)
    
    ```dart
    import 'package:flutter/material.dart';
    import 'package:provider/provider.dart';
    import 'counter_provider.dart'; // <- Your provider class
    
    void main() {
      runApp(
        ChangeNotifierProvider(
          create: (_) => CounterProvider(),
          child: MyApp(),
        ),
      );
    }
    ```
    
    `MyApp.dart`
    
    ```dart
    import 'package:flutter/material.dart';
    import 'package:provider/provider.dart';
    import 'counter_provider.dart';
    
    class MyApp extends StatelessWidget {
      @override
      Widget build(BuildContext context) {
        return MaterialApp(
          home: CounterPage(),
        );
      }
    }
    
    class CounterPage extends StatelessWidget {
      @override
      Widget build(BuildContext context) {
        final counterProvider = Provider.of<CounterProvider>(context);
    
        return Scaffold(
          appBar: AppBar(title: Text('Provider Counter')),
          body: Center(
            child: Text('Counter: ${counterProvider.counter}'),
          ),
          floatingActionButton: FloatingActionButton(
            onPressed: counterProvider.increment,
            child: Icon(Icons.add),
          ),
        );
      }
    }
    ```
    
    ✅
    
    ```
    Provider.of<CounterProvider>(context)
    ```
    
    gets the instance.
    
    ✅
    
    ```
    notifyListeners()
    ```
    
    triggers rebuild of widgets listening to it.
    
- ***Why need Provider?***
    
    
    | Feature | Explanation |
    | --- | --- |
    | 🔄 Automatic UI updates | Widgets automatically rebuild when state changes |
    | 🚫 No manual data passing | No need to pass values through constructors |
    | 🧼 Clean code | Logic in provider, UI in widgets |
    | ✅ Scalable | Good for small to mid-size apps |
- ***When to user Provider?***
    - When you want to **share data** (like user info, theme, locale, etc.) between widgets.
    - When managing **state** like counters, API results, form values, etc.
    - When you want a **simple yet powerful** alternative to `setState`.
