`Navigator 1.0` (what we usually use) works like a **stack** — push/pop screens using route names.

**But it's limited**, especially for:

- Web apps (URL sync)
- Deep linking (e.g., `/home/profile/123`)
- Custom navigation control
- Back button behavior

### ✅ Navigator 2.0 gives you:

- Full control over the **navigation stack**
- Declarative navigation using **state**
- URL ↔ state sync (for web support)

- ***Core Concepts in Navigator 2.0***
    
    
    | Component | Purpose |
    | --- | --- |
    | `Router` | Replaces `MaterialApp.routes`, drives navigation |
    | `RouterDelegate` | Controls how pages are built |
    | `RouteInformationParser` | Converts URLs to app state |
    | `Page` | Represents a screen in the navigation stack |
    | `Navigator` (internal) | Still builds the UI stack |
    
    `Basic flow`
    
    ```dart
    URL → RouteInformationParser → App State
    App State → RouterDelegate → List of Pages → Navigator
    ```
    
- ***Minimal Example (usually used in enterprise level applications)***
    
    `Step 1: Define Pages`
    
    ```dart
    class HomePage extends StatelessWidget {
      final VoidCallback onNext;
    
      HomePage({required this.onNext});
    
      @override
      Widget build(BuildContext context) {
        return Scaffold(
          appBar: AppBar(title: Text('Home')),
          body: Center(
            child: ElevatedButton(
              child: Text('Go to Profile'),
              onPressed: onNext,
            ),
          ),
        );
      }
    }
    
    class ProfilePage extends StatelessWidget {
      final VoidCallback onBack;
    
      ProfilePage({required this.onBack});
    
      @override
      Widget build(BuildContext context) {
        return Scaffold(
          appBar: AppBar(title: Text('Profile')),
          body: Center(
            child: ElevatedButton(
              child: Text('Go Back'),
              onPressed: onBack,
            ),
          ),
        );
      }
    }
    ```
    
    `Step 2: App State`
    
    ```dart
    class AppState extends ChangeNotifier {
      bool showProfile = false;
    
      void goToProfile() {
        showProfile = true;
        notifyListeners();
      }
    
      void goToHome() {
        showProfile = false;
        notifyListeners();
      }
    }
    ```
    
    `Step 3: Create ReouterDelegate`
    
    ```dart
    class AppRouterDelegate extends RouterDelegate<void>
        with ChangeNotifier, PopNavigatorRouterDelegateMixin<void> {
      final AppState appState;
    
      AppRouterDelegate(this.appState) {
        appState.addListener(notifyListeners);
      }
    
      @override
      final GlobalKey<NavigatorState> navigatorKey = GlobalKey<NavigatorState>();
    
      @override
      Widget build(BuildContext context) {
        return Navigator(
          key: navigatorKey,
          pages: [
            MaterialPage(
              child: HomePage(onNext: appState.goToProfile),
            ),
            if (appState.showProfile)
              MaterialPage(
                child: ProfilePage(onBack: appState.goToHome),
              ),
          ],
          onPopPage: (route, result) {
            if (!route.didPop(result)) return false;
            appState.goToHome();
            return true;
          },
        );
      }
    
      @override
      Future<void> setNewRoutePath(void configuration) async {
        // No-op for now
      }
    }
    ```
    
    `Step 4: Main App Entry`
    
    ```dart
    void main() {
      runApp(MyApp());
    }
    
    class MyApp extends StatelessWidget {
      final AppState appState = AppState();
    
      @override
      Widget build(BuildContext context) {
        return MaterialApp.router(
          routerDelegate: AppRouterDelegate(appState),
          routeInformationParser: RouteInformationParserStub(),
        );
      }
    }
    
    class RouteInformationParserStub extends RouteInformationParser<void> {
      @override
      Future<void> parseRouteInformation(RouteInformation routeInformation) async {}
    }
    ```
    
- ***Summary***
    
    ### Navigator 2.0:
    
    - Gives you **declarative control** over navigation.
    - Enables **deep linking, web URLs, and custom transitions**.
    - Is best suited for **complex apps, web, or nested navigation**.
- ***Why use Navigator 2.0?***
    
    ✅ Use it when:
    
    - You need to handle browser URLs
    - You need full control over the stack
    - Your navigation is driven by app state
    
    ❌ Don’t use it for simple apps — stick with `Navigator 1.0` or libraries like `go_router` or `auto_route`.
