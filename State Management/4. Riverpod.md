— modern state management package that

1. Solves Provider’s limitation
2. Is type-safe, testable, and compile-time safe
3. Doesn’t depend on `BuildContext`
4. Works outside the widget tree
5. Supports fine-grained rebuilds (means only the widget that depend on a specific piece of state will rebuild when that state changes and nothing else.)
- ***Why Riverpod over BloC or Provider?***
    
    
    | Feature | setState | Provider | BLoC | Riverpod |
    | --- | --- | --- | --- | --- |
    | Easy for beginners | ✅ | ✅ | ❌ | ✅ |
    | Scales well | ❌ | ⚠️ | ✅ | ✅ |
    | Reusability | ❌ | ⚠️ | ✅ | ✅ |
    | Compile-time safety | ❌ | ❌ | ✅ | ✅ |
    | Boilerplate | Minimal | Medium | High | Low |
- ***Example of Counter App with Riverpod***
    
    `pubspec.yaml` (adding riverpod package to dependency)
    
    ```dart
    dependencies:
      flutter:
        sdk: flutter
      flutter_riverpod: ^2.5.1
    ```
    
    `main.dart`
    
    ```dart
    import 'package:flutter/material.dart';
    import 'package:flutter_riverpod/flutter_riverpod.dart';
    
    // Step 1: Create a provider
    final counterProvider = StateProvider<int>((ref) => 0);
    
    void main() {
      runApp(ProviderScope(child: MyApp()));
    }
    
    class MyApp extends StatelessWidget {
      @override
      Widget build(BuildContext context) {
        return MaterialApp(home: CounterPage());
      }
    }
    
    class CounterPage extends ConsumerWidget {
      @override
      Widget build(BuildContext context, WidgetRef ref) {
        final count = ref.watch(counterProvider);
    
        return Scaffold(
          appBar: AppBar(title: Text('Riverpod Counter')),
          body: Center(
            child: Text('Counter: $count', style: TextStyle(fontSize: 30)),
          ),
          floatingActionButton: Row(
            mainAxisAlignment: MainAxisAlignment.end,
            children: [
              FloatingActionButton(
                heroTag: "increment",
                onPressed: () => ref.read(counterProvider.notifier).state++,
                child: Icon(Icons.add),
              ),
              SizedBox(width: 10),
              FloatingActionButton(
                heroTag: "decrement",
                onPressed: () => ref.read(counterProvider.notifier).state--,
                child: Icon(Icons.remove),
              ),
            ],
          ),
        );
      }
    }
    ```
    
- ***Key concepts of Riverpod***
    
    
    | Concept | Example | Description |
    | --- | --- | --- |
    | `Provider` | `Provider<String>` | Read-only value |
    | `StateProvider` | `StateProvider<int>` | Mutable state (like useState) |
    | `NotifierProvider` | Custom logic | Complex business logic |
    | `ConsumerWidget` | Builds UI using `ref` | Reactively rebuilds |
    | `ref` | Access data, update state | Comes from Riverpod’s scope |
- ***Advantages of Riverpod***
    1. No need of `context.read()` (which Providers uses & it is tightly coupled with UI as context reading is necessary here)
    2. Auto-dispose unused providers (when a provider is not used by any widget it will be automatically cleaned up like a garbage collector)
    3. Logic outside UI
    4. Easy testing
    5. Fast rebuilds
- ***Disadvantages***
    
    — requires functional and reactive programming
    
    — need to understand provider first to transit to it
    
- ***Can be done with Riverpod***
    1. Form validation 
    2. REST API with async `FutureProvider`
    3. Custom Notifier logic `NotifierProvider`
    4. global theme and auth handling
