### 🧠 What Are Widget Rebuilds?

In Flutter, the UI is composed of widgets, and when the state changes, **Flutter rebuilds widgets** to reflect those changes.

However, **unnecessary rebuilds** of widgets can:

- Degrade performance
- Cause UI jank (frame drops)
- Increase CPU usage and battery drain

### 🎯 Goal of Optimization

Ensure that **only the widgets that need to rebuild** do so — **not the entire widget tree**.

- ***Basic of widget rebuilds***
    
    ### 🧱 StatelessWidget vs StatefulWidget
    
    - **StatelessWidget** rebuilds only when it’s recreated.
    - **StatefulWidget** rebuilds when `setState()` is called.
    
    ```dart
    class Counter extends StatefulWidget {
      @override
      _CounterState createState() => _CounterState();
    }
    
    class _CounterState extends State<Counter> {
      int count = 0;
    
      void increment() => setState(() => count++);
    
      @override
      Widget build(BuildContext context) {
        return Column(
          children: [
            Text('Count: $count'),
            ElevatedButton(
              onPressed: increment,
              child: Text('Increment'),
            ),
          ],
        );
      }
    }
    ```
    
    ❗ If this widget is part of a larger tree, calling `setState()` will rebuild everything inside its `build()` method — which can be inefficient.
    
- ***Optimization Techniques***
    
    ### 1. ✅ **Extract Widgets**
    
    Move parts of the UI into separate widgets to **isolate rebuilds**.
    
    ```dart
    class Counter extends StatefulWidget {
      @override
      _CounterState createState() => _CounterState();
    }
    
    class _CounterState extends State<Counter> {
      int count = 0;
    
      void increment() => setState(() => count++);
    
      @override
      Widget build(BuildContext context) {
        return Column(
          children: [
            CountDisplay(count: count), // Only this updates
            ElevatedButton(
              onPressed: increment,
              child: Text('Increment'),
            ),
          ],
        );
      }
    }
    
    class CountDisplay extends StatelessWidget {
      final int count;
      const CountDisplay({required this.count});
    
      @override
      Widget build(BuildContext context) {
        print('CountDisplay rebuilt');
        return Text('Count: $count');
      }
    }
    ```
    
    ✅ `CountDisplay` only rebuilds when `count` changes — the rest of the UI remains untouched.
    
    ### 2. ✅ **Use `const` Constructors**
    
    Widgets marked with `const` don’t rebuild unless explicitly required.
    
    ```dart
    const Text('Static Label') // Never rebuilds unless the parent tree changes
    ```
    
    ### 3. ✅ **Use `ValueNotifier` and `ValueListenableBuilder`**
    
    A lightweight state management tool that avoids full rebuilds.
    
    ```dart
    class CounterWithValueNotifier extends StatelessWidget {
      final ValueNotifier<int> count = ValueNotifier<int>(0);
    
      @override
      Widget build(BuildContext context) {
        return Column(
          children: [
            ValueListenableBuilder(
              valueListenable: count,
              builder: (context, value, child) => Text('Count: $value'),
            ),
            ElevatedButton(
              onPressed: () => count.value++,
              child: Text('Increment'),
            ),
          ],
        );
      }
    }
    ```
    
    ✅ Only the `Text` widget rebuilds — not the entire widget tree.
    
    ### 4. ✅ **Use `Selector` from Provider**
    
    Efficiently rebuilds only what’s necessary based on selected values.
    
    ```dart
    class CounterModel with ChangeNotifier {
      int _count = 0;
      int get count => _count;
    
      void increment() {
        _count++;
        notifyListeners();
      }
    }
    ```
    
    ```dart
    Selector<CounterModel, int>(
      selector: (_, model) => model.count,
      builder: (_, count, __) => Text('Count: $count'),
    )
    ```
    
    ✅ Selector avoids rebuilds of widgets that don’t depend on `count`.
    
    ### 5. ✅ **Use `const` Widgets with `const` Constructors Inside Lists**
    
    In performance-heavy list UIs (like `ListView.builder`), avoid rebuilding children unnecessarily.
    
    ```dart
    ListView.builder(
      itemCount: 100,
      itemBuilder: (context, index) => const ListItem(), // const
    )
    
    class ListItem extends StatelessWidget {
      const ListItem();
    
      @override
      Widget build(BuildContext context) {
        return Text('Item');
      }
    }
    ```
    
    ## 🔍 How to Detect Rebuilds
    
    ### 👀 Use `debugPrint` or `print`
    
    Place print statements in your `build()` methods:
    
    ```dart
    @override
    Widget build(BuildContext context) {
      print('WidgetName rebuilt');
      return ...;
    }
    ```
    
- ***Deep Optimization Example***
    
    ```dart
    class ParentWidget extends StatefulWidget {
      @override
      _ParentWidgetState createState() => _ParentWidgetState();
    }
    
    class _ParentWidgetState extends State<ParentWidget> {
      int count = 0;
      String label = "Hello";
    
      void increment() => setState(() => count++);
      void changeLabel() => setState(() => label = "Hi");
    
      @override
      Widget build(BuildContext context) {
        return Column(
          children: [
            LabelDisplay(label: label),
            CountDisplay(count: count),
            ElevatedButton(onPressed: increment, child: Text('Increment')),
            ElevatedButton(onPressed: changeLabel, child: Text('Change Label')),
          ],
        );
      }
    }
    
    class LabelDisplay extends StatelessWidget {
      final String label;
      const LabelDisplay({required this.label});
    
      @override
      Widget build(BuildContext context) {
        print('LabelDisplay rebuilt');
        return Text(label);
      }
    }
    
    class CountDisplay extends StatelessWidget {
      final int count;
      const CountDisplay({required this.count});
    
      @override
      Widget build(BuildContext context) {
        print('CountDisplay rebuilt');
        return Text('Count: $count');
      }
    }
    ```
    
    ✅ Now, clicking "Increment" **only rebuilds** `CountDisplay`, not `LabelDisplay`.
    
- ***Summary***
    
    
    | Technique | Reduces Rebuilds? | Notes |
    | --- | --- | --- |
    | Extract Widgets | ✅ Yes | Most effective basic method |
    | `const` Constructors | ✅ Yes | Use wherever possible |
    | `ValueNotifier` + Builder | ✅ Yes | Lightweight and reactive |
    | `Selector` with Provider | ✅ Yes | Efficient state listening |
    | List optimization with `const` | ✅ Yes | Helps in list-heavy UIs |
