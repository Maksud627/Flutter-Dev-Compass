BloC = Business Logic Component

It **separates** your app’s logic from the UI:

- **UI** (widgets) just shows what BLoC tells it.
- **BLoC** handles all the processing, decisions, and state.

**Goal**:

✅ No business logic in your widgets.

✅ Easy testing, clean architecture, scalable app.

- ***Basic Idea of  BloC***
    
    UI ➡️ Sends events to ➡️ BLoC
    
    BLoC ➡️ Processes ➡️ Outputs new states
    
    UI ➡️ Listens to states ➡️ Updates itself
    
    > basic building blocks
    > 
    
    | Part | Meaning |
    | --- | --- |
    | **Event** | What happens (e.g., "User clicked button") |
    | **State** | Current situation (e.g., "Counter is 5") |
    | **Bloc** | Middleman: Takes **Event**, gives **State** |
- ***Example of  Counter App without using BloC and the issues with it***
    
    events describe what happens
    
    ```dart
    abstract class CounterEvent {}
    
    class IncrementEvent extends CounterEvent {}
    
    class DecrementEvent extends CounterEvent {}
    ```
    
    creating State that describes current UI situation
    
    ```dart
    class CounterState {
      final int counterValue;
      CounterState(this.counterValue);
    }
    ```
    
    creating manual BloC like pattern
    
    1. Listen to events
    2. Change counter based on event
    3. Send new state to UI through a stream
    
    ```dart
    import 'dart:async';
    
    class CounterBloc {
      int _counter = 0;
    
      // Create stream controllers
      final _counterStateController = StreamController<CounterState>();
      StreamSink<CounterState> get _inCounter => _counterStateController.sink;
      Stream<CounterState> get counter => _counterStateController.stream;
    
      final _counterEventController = StreamController<CounterEvent>();
      Sink<CounterEvent> get counterEventSink => _counterEventController.sink;
    
      CounterBloc() {
        _counterEventController.stream.listen(_mapEventToState);
      }
    
      void _mapEventToState(CounterEvent event) {
        if (event is IncrementEvent) {
          _counter++;
        } else if (event is DecrementEvent) {
          _counter--;
        }
    
        _inCounter.add(CounterState(_counter));
      }
    
      void dispose() {
        _counterStateController.close();
        _counterEventController.close();
      }
    }
    
    ```
    
- ***Benefits of using BloC***
    1. Removes tight coupling between UI and logic
    2. Gives a way of state tracking of the App
    3. Scaling becomes easier
    4. Testing becomes easier
    5. Easy to collaborate in teams
    6. Logic lives separately from the UI
- ***Issues when using BloC***
    1. Verbosity (too much boilerplate)
    2. Slower to set up
    3. Steep learning curve
    4. More boilerplate means more maintenance
    5. Overkill for small features
    6. Debugging streams can be harder
- ***When is BloC a good choice?***
    1. When the app has complex business logic (authentication, pagination, filters etc.)
    2. When in need of predictable state flow
    3. Working in teams
    4. When need of a testable and maintainable code
    5. No need to use BloC when it is a simple app
