When you create a widget in Flutter, it **goes through a series of steps**:

- It **gets created** ➔ **drawn on screen** ➔ maybe **updated** ➔ and then **destroyed**.

🔥 **Full Lifecycle Methods in Order**

| **Method** | **When it's called** | **Purpose** |
| --- | --- | --- |
| **constructor** | When widget is created | Receive initial parameters |
| **createState()** | After widget is created | Create the State object |
| **initState()** | Once when State object is inserted into widget tree | Initialize things (like API calls, animations) |
| **didChangeDependencies()** | Right after initState(), and when InheritedWidget changes | Initialize things that depend on other widgets |
| **build()** | Many times | Render the widget UI |
| **didUpdateWidget()** | When parent widget changes and needs to rebuild | Respond to new widget configuration |
| **setState()** | Manually called to trigger rebuild | Tell Flutter: "My data changed, rebuild me!" |
| **deactivate()** | Before State is removed temporarily | Can clean listeners etc. |
| **dispose()** | When State object is permanently removed | Cleanup (close streams, dispose animations) |

**🗺️ Timeline (Visualization)**

```scss
constructor() → createState() → initState()
    ↓
didChangeDependencies()
    ↓
build() → (setState → build again)
    ↓
didUpdateWidget() (if widget updated by parent)
    ↓
deactivate()
    ↓
dispose()
```

🧠 **In-depth Details of Important Methods**

## 🔹 initState()

- Called **once** when State is created.
- **Never call `setState()` inside initState!**
- Good for:
    - Starting animations
    - Opening database connections
    - Making first API call

```dart
@override
void initState() {
  super.initState();
  _controller = AnimationController(vsync: this);
}
```

## 🔹 didChangeDependencies()

- Called:
    - **Once** after initState()
    - **Again** if an `InheritedWidget` this widget depends on changes
- Good for:
    - Using `Provider.of(context)` safely
    - Using inherited theme or locale settings

```dart
@override
void didChangeDependencies() {
  super.didChangeDependencies();
  final settings = Provider.of<Settings>(context);
}
```

## 🔹 build(BuildContext context)

- **Called often!**
- Every time `setState()` is called, build() is called again.
- Should be **fast and side-effect free** (no API calls inside build).
- Returns a Widget tree.

```dart
@override
Widget build(BuildContext context) {
  return Text('Hello World');
}
```

## 🔹 dispose()

- Called when:
    - Widget is **removed** from tree permanently.
- Good for:
    - Canceling timers
    - Disposing animation controllers
    - Closing streams

```dart
@override
void dispose() {
  _controller.dispose();
  super.dispose();
}
```

- Best Practice to follow proper lifecycle
    - `initState()` ➔ initialize only.
    - `build()` ➔ **only UI code**, no heavy logic.
    - Always `dispose()` your controllers, streams, etc.
    - Use `setState()` wisely — **too many rebuilds = bad performance**.
    - `didUpdateWidget()` is often **ignored**, but **very powerful** for dynamic widgets!
- Trace of a widget lifecycle
    
    ```dart
    class MyPage extends StatefulWidget {
      @override
      _MyPageState createState() => _MyPageState();
    }
    
    class _MyPageState extends State<MyPage> {
      @override
      void initState() {
        print('initState');
        super.initState();
      }
    
      @override
      void didChangeDependencies() {
        print('didChangeDependencies');
        super.didChangeDependencies();
      }
    
      @override
      Widget build(BuildContext context) {
        print('build');
        return Scaffold(
          appBar: AppBar(title: Text('Lifecycle')),
          body: Center(child: Text('Watch console!')),
        );
      }
    
      @override
      void didUpdateWidget(MyPage oldWidget) {
        print('didUpdateWidget');
        super.didUpdateWidget(oldWidget);
      }
    
      @override
      void dispose() {
        print('dispose');
        super.dispose();
      }
    }
    
    ```
